GitHub Copilot を Agent mode にすると、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。VS Code の Copilot Chat では、作業がローカルでリアルタイムに進むため、ツール呼び出しやファイル編集の状況を確認できます。差分をインラインでレビューし、個々の変更を採用または取り消し、フォローアップのプロンプトでエージェントをガイドできます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して採用します。
- セッション中にエージェントをガイドし、ハイコントラストモードに加えてライトモードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードの切り替えも追加してほしいという内容です。新しい会話を始めるのではなく、既存のセッションをガイドして作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する各手順が表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。各ファイルの編集差分には **Keep** と **Undo** の操作が表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、チャット内に差分が表示されます。
    - 変更を採用するには **Keep** を選択します。
    - 変更を取り消して再度試すには **Undo** を選択します。
4. チャット上部の **Files changed** 表示を開くと、このセッション中にエージェントが変更したファイルをすべて確認できます。

> [!NOTE]
> ターミナルコマンドの実行などで許可が必要な場合、エージェントは処理を一時停止し、**Allow** を表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイコントラストモードを実装し終えるまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントをガイドしてライトモードを追加する

ハイコントラストモードができたら、同じ会話でライトモードの切り替えを追加します。同じチャットセッションを続けるため、エージェントはそれまでの作業、編集したコンポーネント、スタイル、ローカルストレージの使用方法などを引き継ぎます。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認し、ライトモード用の更新を提案します。
3. 新しい編集を確認し、ハイコントラストのときと同じように各差分で **Keep** または **Undo** を選択します。
4. たとえば、希望しない方法でトグル UI をリファクタリングしようとした場合は、チャット入力欄の横にある **Stop** ボタンで停止し、明確な指示を送ります。

> [!TIP]
> 進行中のセッションをガイドすると、最初からやり直すより早く済みます。フォローアップのプロンプトで変更を依頼できます。たとえば、「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使用する」、「トグルを 3 つにせず既存の設定パネルにライトモードを追加する」、「両方の切り替えにキーボードショートカットも追加する」などです。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティ指針 (ARIA 属性、キーボード操作、セマンティック HTML、ローカルストレージによる設定保持など) が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の Agent mode を使い、進行中のセッションを監視してガイドしました。ファイル編集を確認して採用または取り消し、コンテキストを保ったままフォローアッププロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を採用または取り消す方法。
- フォローアッププロンプトで進行中のセッションをガイドする方法。

[次のレッスン][next-lesson]では、アクセシビリティ機能の作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが生成した変更をレビューします。
