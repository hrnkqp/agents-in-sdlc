フィルタリング機能の実装、指示の更新、スキルの更新、品質保証 (QA) プロファイル、テストを 1 つのブランチに保存しました。まとめてレビューし、プルリクエストを作成しましょう。星評価のプルリクエスト (PR) は自分でマージしました。今回は **Agent Merge** にプロセスを管理してもらいます。

> [!NOTE]
> 通常は、機能、指示の更新、スキルの更新、QA エージェントを複数の PR に分けます。ワークショップを簡潔にするため、フィルタリングと品質ワークフロー全体を 1 つのセッションとブランチで進め、そのすべての作業をこの PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge と、マージのライフサイクルを自動化する方法を学びます。
- 機能の PR 全体と検証の根拠を確認します。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルタリングのワークフローでは、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys は、マージの承認を開発者の管理下に置いたまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** を使うと、GitHub Copilot app でプルリクエストをマージするまでの残りの作業を自動化できます。有効にすると、アプリのセッションがプルリクエストを読み取り、失敗した継続的インテグレーション (CI) チェックの修正、レビューコメントへの対応、必要に応じたリベースなど、マージを妨げている問題に対処します。GitHub が許可すると、プルリクエストをマージします。バックグラウンドで実行され、アプリを再起動しても継続し、プルリクエストのマージ後に自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge にその作業を任せることもできますが、コードの編集やマージには明示的な承認が必要です。マージを許可する前に、Agent Merge が実行できる操作と作業内容を確認してください。

## Agent Merge で PR を管理する

コードの作成とレビューが完了したら、Agent Merge に PR の処理を任せましょう。

1. エージェントピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンの項目を選択しただけでは開始されません。

Agent Merge の処理が始まります。次の作業を行います。

- タイトルと説明を付けてプルリクエストを作成します。
- issue からセッションを開始した場合は、説明の本文で関連する issue を参照します。
- ターゲットブランチにリベースするか、マージ競合に対処します。
- CI を監視して、すべてのチェックが成功することを確認します。
- 他の開発者や Copilot コードレビューからのフィードバックを監視し、コメントを解決するよう更新します。
- すべてのチェックが成功したら、必要に応じて PR を自動的にマージします。

必要なチェックがすべて成功したら、Agent Merge が PR もマージするよう許可しましょう。

5. マージを許可する前に、PR の差分と検証の根拠を確認します。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. エージェントに明示的にマージを依頼します。

    ```plaintext
    Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
    ```

9. 進行状況を確認し、報告された問題を解決します。続行前に PR の状態が **Merged** になっていることを確認してください。マージ権限を有効にしたことやエージェントが実行中であることは、マージ完了の確認にはなりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリ保護や権限不足を回避しません。続行する前に、それらの問題を解決してください。
